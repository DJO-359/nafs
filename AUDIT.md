## Итог

Главная проблема была не технической, а экзистенциальной: **продукт был
однопользовательским по факту** — все, кто открывал бота, работали в одном
аккаунте владельца. Это закрыто: личность пользователя теперь берётся только
из подписанной строки Telegram `initData`, подпись проверяется по алгоритму
Telegram, тело запроса не влияет ни на что.

Кроме этого исправлены: часовые пояса, из-за которых вечерняя запись уезжала
во «вчера»; «догоняющий шторм» напоминаний после простоя; вечный ретрай на
заблокировавшего бота; обнулённая серия дней; белый экран при сетевой ошибке;
поломка приложения через 7 дней из-за необработанного 401; мёртвая система
уведомлений; отсутствие обработки ошибок на фронте.

Схема БД переведена на миграции, добавлены индексы и уникальные ограничения,
включён `strict` TypeScript в обоих пакетах, написаны тесты на логику, где
были баги, настроен CI.

**Состояние:** типы, линт, тесты и сборка зелёные в обоих пакетах;
приложение поднимается, `/health` отвечает, дыры закрыты (проверено запросами).

## 🔴 Блокеры — исправлены

### 1. Все пользователи работали в одном аккаунте

**Было.** `loginDev()` с захардкоженным `telegramId: "533519962"` был
единственным путём входа во всём приложении. Любой, кто открывал бота, попадал
в аккаунт владельца: читал и правил его дневник, а напоминания уходили ему же.

**Стало.** `loginDev` удалён. `ensureAuth` берёт `window.Telegram.WebApp.initData`
и отправляет на `POST /auth/telegram`. Если сохранённая сессия принадлежит
другому Telegram-аккаунту — сбрасывается.

`frontend/src/hooks/useAuth.ts`, `frontend/src/api/auth.api.ts`

---

### 2. `POST /auth/telegram` выдавал JWT на любой telegramId

**Было.** Эндпоинт доверял `telegramId` из тела запроса. Один `curl` давал
валидный токен на 7 дней от имени любого пользователя.

**Стало.** Появился `TelegramInitDataService`: разбор querystring, сборка
`data_check_string`, `secret_key = HMAC_SHA256(bot_token, "WebAppData")`,
сверка `hash` через `timingSafeEqual`, проверка `auth_date` (не старше часа).
DTO принимает только `initData` и `timezone`.

`backend/src/auth/telegram-init-data.service.ts` — покрыт 6 тестами, включая
подмену `telegramId` внутри подписанной строки.

---

### 3. `JWT_SECRET` молча падал на `'default-secret'`

**Было.** Фолбэк на строку из публичного репозитория в двух местах,
`ConfigModule` без валидации.

**Стало.** `getOrThrow` в обоих местах, Joi-схема на все 15 переменных
(`JWT_SECRET` — минимум 32 символа). Приложение не стартует с неполным
окружением. Добавлены `backend/.env.example` и `frontend/.env.example`.
Секрет в локальном `.env` перевыпущен, curl-заметка с bot-токеном удалена.

`backend/src/config/env.validation.ts`

---

### 4. `GET /users` отдавал всю базу пользователей

**Было.** `findAll()` без `where` и без `attributes`, доступен любому
авторизованному.

**Стало.** Эндпоинт удалён (сейчас отвечает 404), вместо него `GET /users/me`
и `PATCH /users/me`. В модель `User` добавлен `defaultScope` с исключением
`passwordHash`. `POST /users` без валидации тоже удалён.

---

### 5. Белый экран при любой сетевой ошибке

**Было.** `createRoot().render()` вызывался только после успешного
`await ensureAuth()` — метро, холодный старт или CORS оставляли пустой `div`.

**Стало.** Дерево рендерится всегда; авторизация живёт в `AuthGate` на
`useQuery` с состояниями загрузки, ошибки и кнопкой «Повторить». Отдельный
экран для случая «открыто вне Telegram». Добавлены `ErrorBoundary` и
`errorElement` на маршрутах.

`frontend/src/main.tsx`, `frontend/src/app/AuthGate.tsx`

---

### 6. Через 7 дней приложение ломалось у всех

**Было.** Токен из localStorage возвращался без разбора `exp`,
response-интерцептора не существовало.

**Стало.** `ensureAuth` проверяет срок жизни токена, а интерцептор на 401
сбрасывает сессию, перелогинивается один раз и повторяет запрос.

`frontend/src/api/axios.ts`

---

### 7. Вкладка «Статистика» показывала второй календарь

**Было.** Роут `/stats` рендерил `<Calendar/>`, настоящий экран статистики был
недостижим.

**Стало.** `pages/StatsPage.tsx` показывает реальную статистику. Дубликат
`components/Calendar.tsx` удалён.

---

### 8. Часовых поясов не было

**Было.** «Сегодня» считалось двумя несовместимыми способами — через
`toISOString()` (UTC) и через `setHours(0,0,0,0)` (локаль сервера).

**Стало.** У `User` появилась колонка `timezone` (клиент присылает её при
входе). Все вычисления идут через `common/utils/timezone.util.ts`:
`todayInZone`, `dayRangeInZone`, `addDaysInZone`, `addMonthsInZone`.
Границы суток — полуинтервал `[start, end)`. Покрыто 8 тестами.

---

### 9. Схема БД не управлялась ничем

**Было.** Миграций нет, `synchronize` управлялся переменной, а в вашей
локальной конфигурации стоял `true` — при первом же запуске Sequelize пытался
сам перестроить боевую схему и падал.

**Стало.** Введены `sequelize-cli` + две миграции: идемпотентный baseline на
существующие таблицы и миграция новых колонок, индексов и уникальных
ограничений. `DB_SYNC` по умолчанию выключен.

---

### 10. Соединение с Postgres без проверки сертификата

**Было.** `rejectUnauthorized: false`.
**Стало.** Проверка включена, SSL управляется `DB_SSL`.

## 🟡 Важное — исправлено

### Напоминания

| Было | Стало |
| --- | --- |
| «Догоняющий шторм»: после простоя расписание сдвигалось на шаг от старого `remindAt`, и пользователь получал пачку сообщений по одному в минуту | `nextOccurrenceAfter` догоняет расписание до актуального момента за один проход, сообщение уходит одно |
| `lastTriggeredAt` писался, но нигде не читался | Используется для расчёта серии дней |
| `repeatInterval: 0` проходил валидацию → спам каждую минуту навсегда | `@Min(1) @Max(365)`, плюс защита в самой логике повтора |
| `repeatDays` принимал массив строк, и проверка молча не срабатывала | Поэлементная валидация `@IsInt/@Min(0)/@Max(6)` |
| `addMonth` превращал 31 января в 3 марта | `addMonthsInZone` зажимает день по длине месяца |
| Заблокировавший бота вызывал вечный ретрай каждую минуту | Разбор кода ответа: 403 → `telegramBlockedAt` и остановка рассылки, 429 → уважается `retry_after`, прочее → повтор через 5 минут |
| «Через час» на ежедневном давало «завтра + 1 час», а на разовом воскрешало выполненное | Отдельное поле `snoozedUntil`: перенос считается от `now` и не трогает расписание повтора |
| Кнопки в Telegram не гасились, повторные нажатия копили часы | `editMessageReplyMarkup` после обработки |
| IDOR: напоминание искалось по `findByPk` без проверки владельца | Пользователь резолвится по `query.from.id`, поиск идёт по `id + userId` |
| Один сбой БД прерывал весь тик планировщика | `try/catch` на тик и на каждое напоминание, выборка ограничена 500 |

### Данные и запросы

- **Календарь и статистика** больше не выгружают всю историю: появились
  `getBetween(userId, from, to)` и счётчики через `COUNT` в БД.
- **Индексы** добавлены миграцией: `reminders(userId, remindAt)`,
  `reminders(completed, remindAt)`, `reminders(snoozedUntil)`,
  `diary_entries(userId, date)`, `intentions(userId, date)`, `habits(userId)`.
- **Уникальные ограничения** на «одна запись в день»: `intentions(userId,date)`,
  `diary_entries(userId,date)`, `habit_completions(habitId,completedDate)`.
  Гонки ловятся через `UniqueConstraintError`, дубли схлопнуты миграцией.
- **`DiaryEntry.date`** — новая колонка вместо вывода дня из `createdAt`.
- **`onDelete: CASCADE`** на всех связях `User`.
- **Серия дней** больше не обнуляется: учитываются только прошедшие даты, а
  напоминания считаются по `lastTriggeredAt`, а не по будущему `remindAt`.

### Валидация

- `POST /diary` принимал инлайн-тип, который `ValidationPipe` пропускает —
  теперь заполненный `CreateDiaryDto` с ограничением длины.
- `:date` в URL уходил в `new Date()` без проверки и давал 500 — теперь
  `DayParamDto` с маской `YYYY-MM-DD`.
- `?year&month` календаря приходили сырыми строками — теперь `CalendarQueryDto`.
- Даты привычек проверяются на `endDate >= startDate`.
- Три инлайновых объявления `AuthRequest` (одно по ошибке наследовало DOM-тип
  `Request`) заменены единым типом.

### Фронтенд

- **`<Toaster/>` смонтирован** — 7 вызовов `toast` перестали быть мёртвыми.
- **Обработка ошибок**: `onError` во всех мутациях, общий компонент
  `QueryState` с состояниями загрузки/ошибки/пустоты и кнопкой повтора,
  `ErrorBoundary`, `errorElement`.
- **Telegram-интеграция заработала**: подключён `telegram-web-app.js`
  (без него `window.Telegram.WebApp` не существовал вовсе), вызываются
  `ready()` и `expand()`, тема клиента прокидывается в CSS-переменные, учтена
  safe-area, добавлены нативная кнопка «Назад» и тактильный отклик.
- **Инвалидация кэша**: мутации сбрасывают `stats`, `calendar`, `habits`,
  `diary-history`, а не только `day`.
- **`ReminderList`**: 454 → 148 строк. Форму снова можно закрыть, настройки
  повтора подставляются при редактировании и сохраняются, три копии разметки
  заменены одним `ReminderSection`, нативные `alert()` заменены тостами,
  тихие `return` при пустых полях — понятными сообщениями.
- **`console.log` из рендера** убран, `key`-based reset вместо синхронизации
  состояния форм через `useEffect`.
- **Тёмная тема** больше не вспыхивает белым: цвета переведены на токены.

### Инфраструктура

- `helmet`, `X-Powered-By` отключён, CORS из переменной окружения с
  поддержкой preview-доменов Vercel, `credentials` убран за ненадобностью.
- `@nestjs/throttler`: 120 запросов в минуту глобально, 10 на вход.
- Глобальный `AllExceptionsFilter` с `requestId` и маппингом ошибок Sequelize,
  `LoggingInterceptor` с методом, путём, статусом, длительностью и userId.
- `GET /health` с проверкой БД (раньше `AppController` не был подключён и `/`
  отдавал 404).
- Бот поднимается в `onModuleInit`, останавливается в `onModuleDestroy`,
  добавлен `enableShutdownHooks`, появился флаг `TELEGRAM_ENABLED`.
- `strict: true` в обоих пакетах, `.github/workflows/ci.yml`, `.nvmrc`,
  `engines`, единый README вместо двух шаблонных.

## Что нужно сделать вам

1. **Накатить миграции** — без этого приложение упадёт на новых колонках:

   ```bash
   cd backend
   npm run db:migrate
   ```

   Миграции идемпотентны: существующие таблицы не трогаются, дубли за один
   день схлопываются, `diary_entries.date` заполняется из `createdAt`.

2. **Проверить `DB_SYNC=false`** в проде. У вас локально стоял `true`, и
   Sequelize пытался сам перестраивать боевую схему.

3. **Перевыпустить `TELEGRAM_BOT_TOKEN`**, если он ещё жив: он лежал в `.env`
   открытым текстом внутри curl-заметки (я её удалил). Судя по ответу
   `401 Unauthorized` в том же файле, токен уже отозван.

4. **Прописать переменные на проде**: `MINI_APP_URL`, `CORS_ORIGINS`,
   `DB_SSL`, `DB_SYNC=false`, `TELEGRAM_ENABLED=true`, `NODE_ENV=production`.
   Без них приложение не стартует — это сознательное поведение.

5. **Не задавать `DEV_TELEGRAM_ID` на проде.** Даже если задать, маршрут
   `/auth/dev` отвечает 404 при `NODE_ENV=production`, но лучше не хранить.

## Что осталось за рамками

Сознательно не сделано, потому что это уже не «починить существующее»:

- **Webhook вместо polling.** Сейчас бот работает через long polling: при
  нескольких инстансах Telegram отдаёт `409 Conflict`. Для одного инстанса
  всё корректно (добавлены shutdown-хуки), но горизонтально не масштабируется.
- **Состояние диалога бота в Redis.** Хранится в памяти процесса с TTL
  15 минут: при рестарте незавершённый ввод дневника теряется.
- **`HabitsCard` и `HabitsPage`** дублируют друг друга примерно на 70%.
  Баги в них исправлены, но объединение — отдельная задача.
- **Удаление привычки без подтверждения.** У напоминаний диалог есть,
  у привычек — нет.
